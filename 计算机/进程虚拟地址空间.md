我们不妨思考这样一个问题：对于 OS 而言，执行一个 C++ 程序，究竟是如何实现的？从 OS 的视角来看，这整个过程又是什么样的？

对 OS 来说，它并没有 C++ or Python 程序的概念，它看到的只是一个**符合本机可执行文件格式**的**二进制**文件

在 Linux 上，这个格式通常就是 **ELF**。

ELF 全称为 Executable and Linkable Format

它这样组织是方便地告诉操作系统：我的代码和数据在哪里、怎么拼装到内存里、从哪里开始执行

ELF 格式最核心的设计哲学是：**“编译时看节（Section），运行时看段（Segment）”**，同一个文件在不同阶段会被看成不同的样子：

- 链接视角（编译时）：看的是 **Section**（节）。链接器（如 `ld`）把多个 `.o` 目标文件拼成一个可执行文件时，关心的是 `.text`（代码）、`.data`（数据）、`.bss`（未初始化数据）这些 Section。
- 执行视角（运行时）：看的是 **Segment**（段）。操作系统加载器（`execve`）不关心有多少 Section，它只关心**权限**（可读、可写、可执行）。它会把多个具有相同权限的 Section 打包成一个 Segment 加载进内存。

ELF 文件的物理布局（磁盘上的样子）：

```
+--------------------------------------------------+  <-- 文件开头 (Offset 0)
|                   ELF Header (文件头)               |  -- 固定52/64字节，包含魔数、架构、入口点e_entry
|           (e_phoff, e_phnum, e_shoff, e_shnum)    |  -- 指向下面两个表的起始位置和数量
+--------------------------------------------------+
|                                                   |
|             Program Header Table                   |  -- 包含 n 个 Segment 描述（加载视图）
|             ( 段头表 / 程序头 )                    |  -- 操作系统加载时只读这个表
|                                                   |
+--------------------------------------------------+
|                                                   |
|  .text (代码段指令)                                |
|  .rodata (只读字符串常量)                          |
|  .data (已初始化全局变量)                          |  -- 真正的“内容”区，各个Section的数据
|  .bss (未初始化变量，磁盘上占0字节)               |
|  ... (其他节)                                     |
|                                                   |
+--------------------------------------------------+
|                                                   |
|             Section Header Table                   |  -- 包含 n 个 Section 描述（链接视图）
|             ( 节头表 )                            |  -- 链接器和调试器(gdb/objdump)使用
|                                                   |
+--------------------------------------------------+  <-- 文件结尾
```

Section（节） 到 Segment（段） 的映射关系：

```
      链接视图 (Link View)                        执行视图 (Execution View)
    (给 ld 链接器看)                          (给 OS 加载器看)
+----------------------+               +-----------------------------+
|     .text            |               |                             |
|     (指令)           |  ------------>|  Segment 1 (LOAD)          |
|     .rodata          |    打包       |  权限: RX (只读+执行)       |
|     (常量)           |  (同一权限)   |  映射到内存低地址           |
|     .init            |               |                             |
+----------------------+               +-----------------------------+
|     .data            |               |                             |
|     (已初始化)       |  ------------>|  Segment 2 (LOAD)          |
|     .bss             |    打包       |  权限: RW (读写)            |
|     (未初始化,清0)   |  (同一权限)   |  映射到内存高地址           |
+----------------------+               +-----------------------------+
|     .symtab          |               |                             |
|     (符号表)         |  ------------>|  Segment 3 (不加载)        |
|     .debug           |    不加载     |  仅用于调试/链接，         |
|     (调试信息)       |               |  运行时丢弃，不占内存       |
+----------------------+               +-----------------------------+
```

```
高地址 0x7FFFFFFFFFFFFFFF
+--------------------------------------------------+
|                  内核空间 (Kernel)                  |  进程无法访问
+--------------------------------------------------+  <-- 0x00007FFFFFFF0000 (用户态边界)

|             (可读/写/执行 通常禁止执行)            |
+--------------------------------------------------+
|                     ｜                            |
|                     ｜ (内存映射区 mmap)           |  映射共享库(.so)、动态分配大内存
|                     ｜                            |
+--------------------------------------------------+
|             堆 (Heap)                             |  向上增长 (brk/sbrk)，malloc 管理
|             (RW)                                 |
+--------------------------------------------------+
|             未初始化数据 (.bss)                    |  --\
|             (RW, 初始全0)                         |    | Segment 2 (RW)
+--------------------------------------------------+  --/
|             已初始化数据 (.data)                   |
|             (RW, 初值来自文件)                    |
+--------------------------------------------------+
|             只读数据 (.rodata)                    |  --\
|             (R, 字符串常量)                       |    | Segment 1 (RX)
+--------------------------------------------------+  --/
|             代码段 (.text)                        |
|             (RX, 机器指令)                       |
+--------------------------------------------------+
|             [ 可能的 ELF Header 残留 ]            |  通常不映射到内存，或仅映射第一页

|             保留区 (不可访问)                      |  用于捕获空指针访问 (NULL deref)
+--------------------------------------------------+  <-- 0x0000000000000000
低地址 0x0000000000000000
```

#### OS 加载 ELF 的完整流程

当你敲下 `./main` 时，背后发生了这些事：

1.  **Shell 调用 `execve("./main", ...)`**，陷入 Linux 内核。
2.  **内核检查文件头**：读取开头的 `7f 45 4c 46`，确认是合法 ELF。
3.  **读取 Program Header Table**：内核根据表中的描述，调用内存管理单元（MMU）：
    -   在虚拟地址空间为程序分配一段空白区域。
    -   将文件的 `.text` 段拷贝到地址 `0x400000`（比如）并设为只读+可执行。
    -   将文件的 `.data` 段拷贝到地址 `0x600000` 并设为读写。
    -   将 `.bss` 段在内存中扩展出对应大小，全部填零。
4.  **处理动态链接（如果有）**：如果 ELF 头里标记了 `INTERP`（解释器路径），内核不会直接跳转到 `main`，而是先把控制权交给 **动态链接器**（`/lib64/ld-linux-x86-64.so.2`）。由它去加载共享库（`.so`），重定位函数地址（解决 `printf`、`malloc` 的地址），然后再跳转到 `main`。
5.  **跳转到入口地址**：内核（或动态链接器）最后将 CPU 的 `RIP`（指令寄存器）指向 ELF Header 里记录的 **Entry Point**，程序正式跑起来。

其实 Stack 和 Heap 都不是 OS 的虚拟内存机制本身提供的，OS 只是提供了一个 Process 的虚拟地址空间，然后具体的编程语言如何使用这个虚拟地址空间进行管理，就是自己做的了，


Linux 中并没有区分 Process 和 Thread，而是将它们统一抽象为 **Task**

创建 Task 的方法为：

```c
clone(
    CLONE_VM |
    CLONE_FILES |
    CLONE_FS |
    ...
)
```
